# Feature Specs

Create a spec for each important feature before implementation. Keep specs
short, concrete and linked from PR notes when useful.

## Spec Template

```md
# Feature Name

## Problem

What user or operational problem exists?

## Objective

What should be true after this feature ships?

## Scope

What is included?

## Out Of Scope

What is intentionally excluded?

## Endpoints

Affected endpoints, request/response shape and compatibility notes.

## Model

Entities, persistence, migrations or DTOs affected.

## Rules

Business rules, security rules and provider boundaries.

## Tests

Unit, API, integration, docs or smoke validations required.

## Acceptance Criteria

Concrete checks that prove the feature is complete.
```
